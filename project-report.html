Internal Helpdesk / Support Ticketing System

Domain: IT Service Management Tech / Web Application Development

Project brief

Without a structured ticketing system, support requests such as IT issues, HR queries and customer complaints get lost in email inboxes, and nobody is accountable for resolution time. This project builds a ticket queue with prioritization, assignment, SLA-based resolution tracking and threaded internal communication.

Module 1: Requirement analysis and system design

Complete

1. Helpdesk workflow and SLA requirements

Requesters raise tickets, the system assigns them to an agent, the agent works and resolves them, and the requester confirms and closes them. Each priority has a resolution target that starts when the ticket is created.

3. Ticket lifecycle

Open→In Progress→Resolved→Closed

Two backward moves are allowed: In Progress back to Open, and Resolved back to In Progress (reopen). Closed is final.

Module 2: Backend development and database setup

Written, not yet run

1. Ticket creation API

POST /tickets requires a title, description and category, and accepts a priority (default medium). The SLA deadline is set as now() + sla_minutes.

2. Agent assignment

New tickets go to the agent who was assigned least recently (round-robin). Manual assignment is also supported: admins can assign any agent, and agents can take a ticket for themselves.

UPDATE users SET last_assigned_at = now()
WHERE id = (SELECT id FROM users WHERE role = 'agent'
            ORDER BY last_assigned_at NULLS FIRST, id
            LIMIT 1 FOR UPDATE SKIP LOCKED)
RETURNING id, name;

3. SLA timer logic

A background monitor runs every 30 seconds. It marks any open or in-progress ticket past its due_at as breached once, writes a system note to the ticket, and emits a sla.breach event. Ticket queries also return seconds_left and sla_breached so the frontend can show live timers.

Module 3: Core feature implementation

Backend written

1. Status workflow with transition validation

PATCH /tickets/:id/status checks the requested move against the allowed transitions. An invalid move returns a 409 error that lists the allowed next states.

FromAllowed next status
OpenIn Progress
In ProgressResolved, Open
ResolvedClosed, In Progress
ClosedNone

2. Internal comment thread

POST /tickets/:id/comments adds a reply from the requester or an agent. Assignments, status changes, escalations and SLA breaches are logged in the same thread as system notes. Closed tickets are locked.

3. SLA-breach alerts

The monitor records the breach and emits an event. The prototype shows a red banner and a toast for staff. Live push to browsers through WebSocket is the remaining piece.

4. Reassignment and escalation

PATCH /tickets/:id/assignee reassigns a ticket. POST /tickets/:id/escalate raises the priority by one level and recalculates the deadline from the original creation time, so an escalated ticket may be breached immediately.
